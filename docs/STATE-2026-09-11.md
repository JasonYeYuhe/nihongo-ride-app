## The pre-submission review found a blocker in the code and one that was not in the code

Five adversarial reviews, each with its own verifier (`wf_779f85ac-34d`). All findings were in
this round's own work; all were fixed before submitting, each with a test that was shown to fail
against the defect.

- **Blocker, code.** A weak-words cram was folded into the stumble ledger as a "ride", so the
  Stats card's denominator could exceed the ride count printed above it, and the results
  screen's own "ride these words" loop could manufacture a three-run "habit" in three minutes.
- **Blocker, not code.** The LIVE Privacy Policy said "External servers: None. The app does not
  connect to the internet" and "Accounts & sign-in: None"; the Support page (a bound store field)
  said "no network connection at all". iCloud sync has been on by default since v1.13, Game Center
  takes scores, v1.30 added a purchase. All three pages rewritten in both languages; **owner
  approved the push** to the public repo `JasonYeYuhe/nihongo-ride` (`fe6a41a`); the deployed
  pages were curled and confirmed **before** submitting. App Privacy stays `Data Not Collected`;
  no listing field changed (PLAN-WINDOW constraint 4 untouched).
- **Serious:** an unreadable ledger was overwritten on the next ride; "element-lossy decode"
  was a comment over an all-or-nothing decode; `dominantPattern` could freeze forever; the
  Chinese coach rule rendered literal `**`.
- **The gates:** the caffeinate assertion grepped its own line and could never fail; the macOS
  build never ran the launch gate; the store-gate fixtures were strings XCTest cannot print; the
  launch gate's only positive control could skip silently; the horizontal-fit scan could not see
  `return HStack(`; the anti-vacuity floor sat one below the number of gates.
