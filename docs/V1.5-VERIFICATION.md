# v1.5 — On-device verification checklist

These are the **human/device** gates for v1.5 (Custom Word Lists + polish). The
pure logic is unit-tested (`swift test`, 154/28) and the sync path passed a
multi-agent adversarial review; the items below need real devices / a running
app and so must be done by hand. None of this blocks **development**, but all of
it should pass before **submitting** v1.5 (and v1.5 can't be submitted until
v1.4.1 is live — one version in review per platform).

## 1. Release launch self-test (the crash gate — do this first)

macOS 1.4 was rejected for a launch crash (`CKSyncEngine` reentrancy) that only
appeared in a **signed Release** build while the Mac was **signed into iCloud**.
v1.5 added word-list records + a legacy-deck mirror on that same path, so retest:

```
xcodegen generate
xcodebuild -scheme NihongoRide -configuration Release \
  -derivedDataPath build/macrel -allowProvisioningUpdates \
  -destination 'platform=macOS' build
open "build/macrel/Build/Products/Release/Nihongo Ride.app"
```

- Mac must be **signed into iCloud** (that's what fires the `signIn` account
  change at launch — the 1.4 trigger).
- PASS = the app reaches the menu and stays up (no immediate exit). A launch
  crash prints `Fatal error: ... Cannot await a call into CKSyncEngine from
  within a delegate callback` to stderr/Console and exits in <2 s.
- ⚠️ This opens a window and steals focus — run it when you're not mid-task.
- The unsigned `CODE_SIGNING_ALLOWED=NO` build I use for compile checks does NOT
  exercise CloudKit (no entitlement), so it can't substitute for this.

## 2. Two-device iCloud read-verify (same account)

Two devices on the **same** iCloud account (e.g. iPhone "js" + the Mac), iCloud
sync ON in Settings on both. Verify each merge converges:

| Data | Action | Expected after both sync |
|---|---|---|
| SRS | review words on A | newer `lastReviewed` wins on B (no progress lost) |
| Ride log | ride on both | both rides present (union by UUID) |
| Lifetime odometer | rides on both offline, then sync | totals **sum** across devices (not max) |
| Word list — add | ★ a word on A, a different word on B (concurrent) | **both** words on both (ids union / add-wins — nothing dropped) |
| Word list — name | rename a list on A | rename shows on B (name LWW) |
| Word list — delete | delete a named list on A | list disappears on B (soft-delete tombstone propagates) |
| Default ★ list | both devices | a single "★ Saved" list, **not** two (constant id `"default"`) |

Note (documented MVP behavior, not a bug): **un-saving / removing a single word
does NOT propagate** — the peer's union re-adds it. Only whole-list delete/clear
propagates. Word lists are the user's **private** iCloud content (App Privacy
stays "Data Not Collected").

## 3. Cross-version convergence (1.4.1 ⟷ 1.5, same account)

The reason the legacy `SavedWords:deck` record is now a **permanent two-way
mirror** of the default list (the adversarial review caught data loss in the
earlier one-time scheme). One device on **1.4.1**, one on **1.5**, same account:

1. ★ a word on the **1.4.1** device → after both sync, it appears in the **1.5**
   device's default "★ Saved" list (incoming deck folded into the default).
2. ★ a different word on the **1.5** device → after both sync, it appears in the
   **1.4.1** device's saved deck (1.5 re-writes the deck mirror on default edits).
3. Repeat #1 a second time **after** the first sync settled → it still arrives on
   1.5 (this is the exact case the review flagged: a one-time window would have
   silently dropped it; the permanent mirror must not).
4. No zombie list resurrection: a list **deleted** on 1.5 stays gone (deletes
   travel as the tombstone field, not via the deck).

Record the run + any anomaly here or in the memory file. This is the highest-risk
real-world scenario; leave buffer for a fix if it surfaces a bug.

## 4. Accessibility (C3) — verify the labels actually read

Code adds `accessibilityLabel`/`Hidden` across screens; verify on the platforms:

- **macOS** — Xcode → Open Developer Tool → **Accessibility Inspector**. Run the
  audit on each screen (menu / results / settings / **lists** / **list detail** /
  **onboarding** / journey HUD). Fix any "element has no label" hits.
- **iOS (device)** — turn on **VoiceOver**, swipe through each screen and use the
  **rotor**; confirm every interactive control (★ toggle, list rows, play /
  rename / delete, "add to lists" sheet, mode/level pickers, settings toggles,
  onboarding Next/Skip) is announced meaningfully.
- **Dynamic Type** — Settings → Accessibility → Display & Text Size → Larger Text,
  set to the **largest** size. Smoke-test the NEW screens (Lists, list detail,
  onboarding) + menu/results/settings: body/explanatory text grows and nothing is
  clipped or overlapping. (Game word-card text is intentionally fixed to protect
  layout.) ImageRenderer ignores Dynamic Type, so this can only be checked here.

## 5. Touch / keyboard (2.1a regression guard)

On a touch-only iPad (hardware keyboard off):

- In a ride, **long-press ★** → "Add to lists" sheet opens; the ride does NOT
  advance underneath; on dismiss the **software keyboard returns** (typing works).
- Every list's "practice" button starts a ride (or no-ops cleanly if the list has
  no resolvable words — never a blank stuck screen).
- Create / rename a list: the native alert's text field shows the keyboard; the
  list screen itself does not summon a keyboard otherwise.
